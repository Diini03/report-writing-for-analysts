# Lesson 4 — Reports Inside Power BI

## Why this lesson matters

Lessons 1–3 taught you what a report _is_ — a written document. But you're a Power BI user, and the question you actually got asked was "how do you prepare a report after the dashboard," meaning: inside a tool that's built for visuals, where does the writing actually go? This lesson answers that directly.

There are two honest answers, and a good analyst uses both.

## Answer 1: Power BI is not primarily a writing tool

This has to be said plainly: Power BI is built for interactive exploration, not prose. Trying to cram a full six-part written report (Lesson 3) into a dashboard usually makes it worse, not better. Most real-world workflows pair Power BI (the "what happened," explorable) with a separate written report (the "why and what next," Word/PDF/email/Notion) — and that pairing itself is a legitimate answer to "how do you report after a dashboard."

Don't be afraid to say that in an interview. It shows judgment, not a gap.

## Answer 2: But Power BI does have real reporting features — know them

### Text boxes and titled visuals

The simplest tool — a text box with a 1–2 sentence "so what" placed directly above or beside the relevant chart. This is the minimum bar: **never ship a chart with no explanation next to it.** A bare bar chart forces the reader to do your job for you.

### Tooltips (report page tooltips)

A small hidden page that appears on hover, giving context or a mini-breakdown without cluttering the main view. Good for a one-line "why" behind a specific data point without needing a separate document.

### Bookmarks + Selection Pane

Used to build a guided "story" through a dashboard — click through a sequence of pre-set views, each revealing a different insight in order. This is the closest Power BI gets to a written narrative: you're forcing a reading order onto an otherwise free-form dashboard.

### The "Analyst" / narrative visual approach

Adding a dedicated page (often the _first_ page of the report) styled like a written executive summary — using text boxes structured like Lesson 3's skeleton (Summary, Key Findings, Recommendation) sitting above or beside the supporting visuals. This is the most direct way to put a real written report _inside_ the Power BI file itself.

### Paginated Reports (Power BI Report Builder)

A separate Power BI tool built specifically for pixel-perfect, printable, PDF/Word-style documents — built for exactly the kind of formal written report from Lesson 3, generated from the same underlying data model. Worth knowing this exists, even if you haven't used it yet — mentioning it in an interview signals real tool depth.

### Export to PDF / PowerPoint

The most common real-world path: build the dashboard, then use Power BI's built-in export to hand off a static PDF or PPT — often with a written summary added on the first slide/page outside the tool itself.

## What to actually say in an interview

If asked "how do you report after a dashboard," a strong answer sounds like:

> _"The dashboard itself carries a short narrative page or text-box summaries next to key visuals, following the Executive Summary and Key Findings structure. For a formal audience, I export that alongside a written report — Word or PDF — using the Insight and Recommendation sections that don't fit naturally inside the dashboard."_

That answer shows you know **both** halves — the in-tool reporting features, and when to step outside the tool entirely. That combination is what was missing before.

## Quick check

1. Name two Power BI features that let you add written narrative directly inside a dashboard.
2. In your own words, why shouldn't a full six-part written report be crammed entirely into dashboard text boxes?
3. Look at your Somalia displacement classifier dashboard (or any Power BI project you've built) — where would a one-line "so what" text box make the biggest difference right now?
